지난 주 부터 [[맞다AI가]]의 [웹 페이지](https://matdaaiga.kr/) 프로젝트를 진행중이다. 
기존의 프로젝트에 Linktree 같은 링크 모음 기능을 추가한다. 
기존 프로젝트는 작성한 markdown을 기반으로 자동으로 정적 웹 페이지를 만들어준다. 
여기에 YAML 파일을 추가하였다. 
정해진 형식의 YAML파일을 추가하면 이를 markdown 형식으로 변환하는 것이 내가 맡은 기능이다. 
이를 시영님과 같이 진행한다. 
시영님은 link 페이지를 위한 css를 위주로 담당, 
나는 YAML 파일을 Markdown 앱으로 변환하는 .NET 콘솔 앱 개발을 담당한다. 

.NET 개발은 경험한 적 없다. C#도 제대로 배운 적 없다;;

막상 해보니 별 것 아니었다. 
이따금 처음 보는 문법이 나오지만 GPT에게 물어보면 그만이다. 

YAML 파일의 구조를 정의하는 JSON 문서 작성 부터 쉽지 않았다. 
엥 JSON? 그냥 작성하면 되는거 아님? ㅇㅇ 아님..
내가 생각한 것과 다른 부분이 많았다. 
꼭 구조가 이래야만 하는지, 더 효율적인 구조는 없을지, 굳이 작성하지 않아도 될 코드가 중복으로 들어가지는 않았는지..
JSON으로 YAML의 구조를 정의하는 것이 처음이다 보니 설정 방법도 생소했기에 더 어려움을 느꼈다. 
무한 PR과 무한 review 끝에 간신히 merge 되었다. 

그 다음은 `IConverterService.cs`를 작성한다. 이름 그대로 인터페이스다. 
프론트엔드 리액트 개발을 시작으로 제대로 공부하기 시작했기 때문에 객체지향이 익숙하지 않았다. 
간단한 앱인데 굳이 인터페이스를 작성해야하나? 싶어 질문을 했다. 
미리 밑그림을 그리는 것은 물론이고 테스트에 용이하다고 한다. 
그리고 특별한 주석(?)도 배웠다. 

```csharp
/// <summary>

/// Loads data from a specified file and deserializes it into an object.

/// </summary>

/// <param name="filepath">the path of data source</param>

/// <returns>Returnss <see cref="LinkCollection"/> instance.></returns>

Task<LinkCollection> LoadAsync(string filepath);
```

이런식으로 HTML마냥 태그를 사용해 주석을 사용한다. 
리액트 개발에도 `@param` 처럼 주석을 달고는 했었다. 
당연히 C#을 비롯한 다른 언어에도 있을 만 하지만.. 왜 생각을 못했을까?

Justin님의 리뷰를 보며 영문 주석 작성 스타일도 조금 배운 것 같다. 
예를 들어, 내가 `returns LinkCollection that represents...` 라고 장황하게 설명한 부분이 있다면 위의 코드 처럼 `Returns LinkCollection instance` 라고 간결하고 정확한 의미 전달이 될 수 있게 고쳐주셨다.
