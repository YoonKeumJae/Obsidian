# Azure Backup이란? 

## Azure Backup이란? 

데이터를 백업하고 Azure 클라우드에서 복구할 수 있는..
간단, 안전, 비용 효율적인 솔루션. 

![온-프레미스 환경에서 클라우드에 백업 에이전트를 구현하는 Azure Backup 서비스에 대한 다이어그램. 중간 섹션에는 중앙 관리를 나타내는 기본 막대와 함께 보안 및 스케일링 성능에 대한 Azure Backup의 구성 요소가 표시됩니다.](https://learn.microsoft.com/ko-kr/training/modules/intro-to-azure-backup/media/azure-backup-overview.png)

## Azure Backup 정의

Azure가 관리하는 데이터 자산 일체에 백업 솔루션 제공함. 
중앙 집중식 관리 인터페이스로 백업 정책 정의함. 
VM, Azure Disk, SQL, SAP DB, Azure 파일 공유 등의 광범위 엔터프라이즈 워크로드 보호 가능.

![맨 아래의 워크로드가 데이터를 생성하여 위로 데이터 평면에 전달하고, 관리 평면에 연결되는 구조를 보여주는 Azure Backup 아키텍처 다이어그램. 관리에는 백업 정책, Azure 정책, Azure Monitor, Azure Lighthouse 서비스가 포함됩니다.](https://learn.microsoft.com/ko-kr/training/modules/intro-to-azure-backup/media/azure-backup-architecture.png)

## 주요 특징

- 제로 인프라 백업 솔루션
	- 백업 서버, 인프라 필요없음
	- 백업 스토리지 배포 안해도 됨 - Azure Backup이 자동으로 관리, 스케일링
	- 자본 지출 없애고 운영 비용 절감
	- 스토리지 관리 자동화, 사용 편의성 향상
- 대규모 관리
	- "백업 센터" 라는 중앙 콘솔에서 전체 백업 공간 관리
	- API, PowerShell, AzureCLI로 백업 정책, 보안 구성 자동화
	- 하나의 통합 콘솔에서 백업 관리 지원 -> 대규모 데이터 보호 관리 간소화 -> 운영 효율 증가
- 보안
	- 암호화, private endpoint, 알림 사용 -> 데이터 전송 유무와 관계없이 백업 환경에 기본 보안 제공
	- 랜섬웨어, 악의적 관리자, 실수로 인한 삭제 등으로 부터 보호

## 복구 시간 목표, 복구 지점 목표

- RTO (복구 시간 목표)
	- 재해 발생 후 복원해야하는 시간
	- 예) RTO가 4시간 = 재해 발생 시 최대 4시간의 가동 중지만 허용
- RPO (복구 지점 목표)
	- 조직이 이벤트 동안 견딜 수 있는 최대 데이터 손실량 (단위: 시간)
- 예시
	- 조직은 DB에 1시간의 RPO 가짐: 매 시간 백업 수행
	- 한 번의 데이터 손실 발생 : 1시간 이하의 데이터 손실
	- RTO 3시간으로 설정: 3시간 이내에 DB 복구를 목표함

# Azure Backup 작동 방식

Azure Backup의 아래 항목들에 대해 다뤄보자. 

- 워크로드 통합 레이어 - 백업 확장
	- Azure VM || Azure Blob 등 실제 워크로드와 통합이 이뤄지는 계층
- 데이터 평면 - 액세스 계층
	- 백업을 저장할 수 있는 세 가지 액세스 계층이 있음
		- 스냅샷 계층
		- 표준 계층
		- 보관 액세스 계층
- 데이터 평면 - 가용성 및 보안
	- 사용자가 지정한 중복도에 따라 여러 영역, 지역에 복제됨
- 관리 평면 - Recovery Services 자격 증명 모음 / Backup 자격 증명 모음 및 백업 센터
	- 자격 증명 모음 << 백업 서비스와 사용자가 상호작용 할 수 있는 인터페이스 제공

## 어떤 데이터를 어떻게 백업하나요? 

쉽게 말하면..
(온프레미스 || VM)에서 실행되는 데이터, 상태, 워크로드를 Azure 클라우드로 백업하는 것. 
백업 된 데이터를 Recovery Services 자격 증명 모음, Backup 자격 증명 모음에 저장함. 

- 온프레미스 Windows의 경우
	- Azure Backup MARS(MS Azure Recovery Services) 에이전트를 사용해 Azure에 직접 백업 가능
	- Windows PC를 System Center DPM(Data Protection Manager) 또는 MABS(Microsoft Azure Backup Server)와 같은 백업 서버에 백업
		- 이후 해당 서버를 Azure의 Recovery Services 자격 증명 모음에 백업
- Azure VM의 경우
	- 직접 백업 가능
	- VM에서 실행중인 Azure VM 에이전트에 백업 확장 설치 -> 전체 VM 백업
	- VM 파일, 폴더만 백업 -> MARS 에이전트 실행

Azure backup << 자격 증명 모음(Recovery Services 자격 증명 모음, Backup 자격 증명 모음)에 백업된 데이터 저장함.
여기서의 자격 증명 모음은 뭐냐? 
백업 복사본, 복구 지점, 백업 정책 등의 데이터 보관하는데 쓰는 Azure 온라인 스토리지 엔터티임. 
그러니까...
백업된 데이터를 Azure 온라인 스토리지에 저장한다는 뜻임.

## 지원되는 백업 유형

- 전체 백업
	- 최초의 백업 = 전체 백업
- 증분 백업
	- DPM/MABS에서 디스크 백업에 사용
	- Azure에 대한 모든 백업에 사용
	- 백업 후 변경된 데이터 블록 백업에만 집중함

Azure Backup은 SQL Server 백업 형식도 지원함. 
아래 표를 참고하자. 

|     형식     | 설명                                                                                                                                                        | 사용                                                                                 |
| :--------: | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
|   전체 백업    | 전체 DB 백업. 특정 DB, 파일 그룹, 파일 세트의 모든 데이터 포함. <br>데이터 복구를 위한 로그 또한 포함됨.                                                                                       | (많으면) 하루에 하나의 전체 백업 트리거 가능. 매일 or 매주 전체 백업 수행하도록 선택 가능.                            |
|   차등 백업    | 가장 최근의 전체 데이터 백업 기반. 전체 백업 후 변경된 데이터만 캡쳐.                                                                                                                 | (많으면) 하루 한 번 트리거 가능. 전체 백업과 같은 날 구성 불가.                                            |
| 하루에 여러번 백업 | RPO 최소 4시간, 최대 24시간으로 매 시간 VM 백업                                                                                                                          | 향상된 백업 정책 사용. (신뢰가능한 시작 VM 등의) 새 Azure 제품에 대해 백업 일정을 각각 4, 6, 8, 12, 24시간으로 설정 가능. |
| 선택적 디스크 백업 | VM에 연결된 데이터 디스크 하위 집합 선택적 백업. 이후 즉시 복원과 자격 증명 모음 계층 모두에서 사용 가능한 디스크의 하위 집합 복원. <br>VM 디스크 하위 집합의 중요 데이터만 관리하는데 도움됨. <br>비용 절감을 위해 OS 디스크만 백업하려는 경우 사용 가능. | 선택적 디스크 백업 및 복원 기능 제공.                                                             |
|  트랜잭션 로그   | 특정 시간(초 단위) 까지의 특정 시점 복원 가능                                                                                                                               | 많으면 15분 마다 트랜잭션 로그 백업 구성 가능.                                                       |

# 워크로드 통합 레이어 - 백업 확장

워크로드 관련 백업 확장 << 원본 VM || 작업자 VM에 설치됨.
정책에서 사용자가 정의 한 대로 백업됨. 
이때 백업 시, 백업 확장에서 아래의 백업을 생성함. 

- 스토리지
	- Azure VM | Azure Files 사용할 때 스냅샷
- 스트림 백업
	- VM에서 실행되는 SQL | HANA와 같은 DB의 경우

백업된 데이터는( NSG, 방화벽, 또는 더 정교한 Private endpoint를 사용해) Data Plane의 Azure 관리 스토리지로 전송됨. 

## Data Plane - 액세스 계층

백업을 저장할 세 계층이 있음. 

- 스냅샷 계층
	- VM 백업의 첫 단계
	- 스냅샷을 촬영하여 디스크와 함께 저장됨 -> 스냅샷 계층
	- 스냅샷 계층 복원 << (복원 트리거 직전, 자격 증명 모음에서 스냅샷 복사될 때 까지) 기다리는 시간이 없음 << 자격 증명 모음에서 복원하는 것 보다 빠름!
	- VM, Azure Files 등의 스냅샷 << 지정된 리소스 그룹의 구독에 보존됨
		- 이 컨테이너는 백업, 스냅샷을 고객이 로컬로 사용 가능. 빠른 복원 가능. 
		- 지정된 리소스 그룹의 구독에 컨테이너가 있고.. 컨테이너에 저장되는 것 같음..
- 자격 증명 모음 표준 계층
	- 모든 워크로드의 백업 데이터는 자격 증명 모음에 저장됨
	- 이 "자격 증명 모음"은 Azure Backup에서 관리하며, 자동 스케일링을 지원하는 스토리지 계정 세트임
	- Microsoft 관리형 테넌트에 격리된 백업 데이터 복사본 저장 << 추가 보호 계층 생성 가능한 온라인 스토리지
	- 스냅샷 지원되는 워크로드인 경우) 스냅샷 계층, 자격증명모음 계층 모두에 백업 데이터 복사본 있음
	- 백업 데이터 원본이 삭제되거나 손상돼도 백업 데이터 사용 가능
- 보관 계층
	- (조직의 준수 규칙에 정의된 요구사항을 갖춘 LTR(장기 보존) 백업 데이터를 포함한) 백업 데이터 저장을 위해 사용
	- 대부분 이전 백업 데이터는 거의 액세스 X, 준수 요구 사항에 한해 저장
	- 장기 보존 지점의 백업 지원

모든 계층은 서로 다른 RTO 제공, 가격 다름.

## 데이터 평면 - 가용성, 보안

백업 데이터 << 지정된 중복도에 따라 여러 지역 사이에서 복제됨. 
LRS(로컬 중복 스토리지), GRS(지역), ZRS(영역, 지역의 상위 범위) 중 선택 가능. 
아무튼 고가용성 데이터 스토리지 기능 제공함. 

데이터 암호화, RBAC 구현하여 데이터 안전하게 유지. 
백업, 복원 수행 가능한 사용자 선택함. 
일시 삭제 작업을 사용해 악의적인 백업 삭제 방지. 
삭제된 백업 << 14일 간 비용없이 저장됨. 필요 시 복구 가능.
백업 데이터 수명 주기 관리 시나리오 또한 지원함. 

![Azure RBAC, 암호화 및 일시 삭제의 세 가지 보안 옵션을 아이콘으로 표시하는 그래픽.](https://learn.microsoft.com/ko-kr/training/modules/intro-to-azure-backup/media/built-in-security.png)

## Management Plane - Recovery Services 자격 증명 모음 / Backup 자격 증명 모음 및 백업 센터

Recovery Services 자격 증명 모음 + Backup 자격 증명 모음 -> 백업 오케스트레이션 + 관리
자격 증명 모음으로 백업 데이터 저장. 
자격 증명 모음 << 백업 서비스와 상호작용 가능한 인터페이스 제공.. 
*했던 말 계속 또 하고 있네.. 그만큼 중요하겠지..*
아무튼, 자격 증명 내 Azure Backup 정책은 백업 트리거되는 시기, 보존 기간 정의함. 

단일 자격 증명 모음, 여러 자격 증명 모음 << 백업 구성, 관리 가능. 

- 단일 자격 증명 모음
	- 단일 구독, 단일 리소스로 워크로드 관리하는 경우 사용
	- 백업 공간 모니터링, 관리
- 여러 자격 증명 모음
	- 여러 구독에 분산된 워크로드 관리하는 경우 사용
	- 구독 당 하나 이상의 자격 증명 모음 생성 가능

![관리 평면의 다이어그램. Recovery Services 자격 증명 모음은 포털, SDK 또는 CLI(명령줄 인터페이스)를 통한 백업 정책 및 관리에 대한 옵션을 보여 줍니다.](https://learn.microsoft.com/ko-kr/training/modules/intro-to-azure-backup/media/backup-vaults.png)

백업 센터로 백업 관련 모든 작업 관리 가능함. 
Azure 환경에서 잘 작동하게 설계됐음. 
백업 센터를 사용해 여러 워크로드 유형, 자격 증명 모음 등의 백업을 효율적으로 관리 가능. 

# Azure Backup을 사용해야 하는 경우

Azure Backup이 사용자 요구사항에 적합한지 알아보자. 
일반적인 백업 시나리오에서는 아래 헤택을 제공함. 

- 데이터 가용성 보장
- Azure 워크로드 보호
- 데이터 보호

## 의사 결정 기준

Azure VM, Azure Disks 등 광범위한 엔터프라이즈 워크로드를 보호함. 
아래 표는 평가 주요 기준임. 
데이터 보호를 위해 서비스 제공 가능한 몇 주요 영역 포함돼있음. 

|     조건     | 고려사항                                 |
| :--------: | ------------------------------------ |
| Azure 워크로드 | Azure VM, Azure Blob, Azure Disks 등  |
|   규정 준수    | 여러 (영역 \|\| 지역)에 장기 보존되는 고객 정의 백업 정책 |
|   운영 복구    | 셀프 서비스, 백업으로 복구 가능                   |

## 조건 적용

SQL Server가 세 개의 VM에서 실행되고 있다 하자. 
규정 요구사항 충족하려면 백업 데이터를 최대 10년간 보존해야 함. 
백업 모니터링도 가능해야 함. 

## Azure Backup이 SQL Server 인스턴스 호스팅하는 VM 보호 가능한가? 

백업 확장으로 Windows, Linux VM 백업 가능. 
-> SQL Server 호스트하는 전체 VM 백업 가능. 
Azure VM에서 파일, 폴더, 시스템 상태만 백업하려면 MARS 에이전트 사용 가능함. 

SQL Server 데이터만 백업하는 것도 지원함. 
VM에서 실행되는 SQL Server 백업하는 스트림 기반 특수 솔루션 제공함. 
인프라 없는 백업, 장기 보존, 중앙 관리라는 Azure Backup의 이점과 맞아떨어짐. 

또한 SQL Server를 위해 특별히 추가적인 이점을 제공한다는데...

- 모든 백업 유형 지원하는 워크로드 인식. 전체, 차등, 로그 백업
- 15분 RPO와 잦은 로그 백업
- 지정 시간 복구 최대 1초
- 개별 DB수준 백업 및 복원

## Azure Backup 규정 준수에 도움되나?

백업에 필요한 접근 제어 메커니즘 구현 가능. 
자격 증명 모음(Recovery Services, backup 자격 증명 모음) << 관리 기능 제공 + Portal, backup center, 자격증명모음 대시보드, SDK, CLI, REST API를 통해 접근 가능. 
Azure RBAC 지원, 백업 관리자 설정 옵션 제공. 

단기 보존 << 분 단위 || 일 단위 
장기 보존 << 주 단위 || 월 단위 || 연 단위

장기 보존 가능한 경우는.. 

- 계획됨 (규정 준수 요구 사항)
	- 현재 시점으로 부터 수년 후 데이터 필요할 것을 미리 아는 경우
- 계획되지 않음 (주문형 요구 사항)
	- 미리 알지 못하는 경우 
	- 특정 사용자 지정 보존 설정과 함께 주문형 백업 사용가능
		- 사용자 지정 보존 설정 << 정책 설정 영향 받지 않음
- 사용자 지정 보존을 통한 주문형 백업
	- 예약되지 않은 백업 << 주문형 백업 사용 가능
	- 예약 백업에 적합하지 않거나, 세분화 된 작업 수행하는 경우 유용
	- 하루에 하나의 백업만 허용 -> 매일 여러번 IaaS 백업하는 경우 해당됨
	- 예약된 정책의 보존 정책 << 주문형 백업에 적용 X

규정 준수를 위해 정책 관리 구현할 수 있음. 
각 자격 증명 모음 내에 존재. 
백업이 트리거되는 시기, 보존돼야하는 기간 정의. 
정책 관리 << 여러 항목 적용 가능.
