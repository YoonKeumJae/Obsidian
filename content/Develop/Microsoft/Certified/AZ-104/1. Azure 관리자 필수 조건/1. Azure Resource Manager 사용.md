# Azure Resource Manager 혜택 검토

- 리소스를 그룹으로 사용 가능. 
- 모든 리소스 배포, 업데이트, 삭제 가능
- 배포 템플릿 사용 -> 여러 환경(테스트, 스테이징, 프로덕션 등)에서 사용 가능
- 배포 후 리소스 관리: 보안, 감사, 태그 등의 기능

2. API: Azure Resource Manager에 요청 전달
3. Azure Resource Manager: 요청 인증, 권한 부여
4. 적절한 리소스 공급자로 요청 라우팅

4. Azure Resource Manager는 요청 인증, 권한 부여

## 이점

- 리소스를 그룹으로 묶어 한번에 배포, 관리, 모니터링
- 솔루션의 반복적인 구현, 리소스를 일관적인 상태로 배치
- 선언적 템플릿으로 인프라 관리
- 리소스 간 종속성 정의, 올바른 순서로 배포
- RBAC(Role Based Access Control)는 관리 플랫폼으로 통합됨 -> 그룹의 모든 서비스에 Access Control 적용 가능. 
- 리소스에 태그 적용하여 논리적으로 구성
- 같은 태그인 그룹들에 대한 비용 확인 가능

## 지침

- Azure Resource Manager 템플릿의 선언적 구문을 통해 인프라 정의, 배포. 
- 템플릿에서 모든 배포, 구성 단계 정의 (솔루션의 수동 설정 단계 없어야).
- 명령적 명령?? 을 실행하여 리소스 관리(앱 시작, 중지 등).
- 리소스 그룹 내부 리소스를 동일한 수명 주기로 정렬. 모든 다른 구성에 태그 사용. 

# Azure 리소스 용어 검토

## 리소스
Azure를 통해 사용할 수 있는, 관리 가능한 항목. 
가상 머신, 스토리지 계정 등이 여기에 포함됨. 

## 리소스 그룹
리소스들의 집합. 솔루션에 필요한 모든 리소스를 포함하거나, 특정 리소스만 포함시킬 수 있음. 

## 리소스 공급자
Resource Manager를 통해 배포하고 관리할 수 있는 리소스, 작업을 제공하는 서비스. 
키, 암호 제공하는 경우 Microsoft.KeyVault 사용. 
Microsoft.KeyVault는 '자격 증명 모음' 이라는 리소스 유형 제공함. 
Microsoft.Compute, Microsoft.Storage, Microsoft.Web이 포함됨. 

> 리소스 배포 이전에 사용 가능한 리소스 공급자를 이해해야 함. 
> 리소스 공급자, 리소스 이름을 알고있으면 배포하려는 리소스 정의 가능. 
> 리소스 종류에 대한 유효한 위치, API 버전 알아야 함. 
## 템플릿
리소스 그룹에 배포할 리소스들을 정의하는 JSON. 배포된 리소스 사이 종속성 정의. 
리소스를 일관적, 반복적으로 배포하는데 사용됨. 

## 선언적 구문
만들고자 하는 대상을 선언하는 구문. Resource Manager 템플릿이 해당됨. 
파일에서 Azure에 배포하는 인프라에 대한 속성 정의. 

# 리소스 그룹 만들기

그룹에 리소스 배포 << 템플릿 실행을 추적할 수 있음.
배포 실패 시 이유 표시됨. 
그룹(에 대한 단일 리소스) 또는 템플릿에 관계없이 오류 수정, 배포할 수 있음. 

## 고려 사항

- 리소스는 하나의 리소스 그룹에만 존재할 수 있음.
- 리소스 그룹의 이름을 바꿀 수는 없음.
- 리소스 그룹 내에 다양한 리소스가 있을 수 있음.
- 리소스 그룹 내에 여러 (물리적) 지역의 리소스가 있을 수 있음.

## 리소스 그룹 만들기

리소스 그룹 정의할 때 고려해야 할 주의사항들

- 모든 리소스는 동일한 수명 주기 공유해야 함. 
	- (DB, 서버 등) 하나의 리소스에 다양한 배포 주기가 존재한다면 다른 리소스 그룹에 있어야 함.
- 언제든지 리소스 그룹에 리소스를 추가, 제거할 수 있음.
- 리소스를 다른 리소스 그룹으로 이동할 수 있음(제한 적용됨).
- 다른 (물리적) 지역에 있는 리소스를 그룹에 포함시킬 수 있음.
- 접근 권한 범위 지정에 리소스 그룹 사용 가능.
- 리소스는 다른 그룹의 리소스와 상호작용 할 수 있음 (수명 주기가 다른 경우가 대부분).

리소스 그룹 생성 시 물리적 위치를 제공해야 함. 
그룹 내부에 리소스가 존재한다면, 그룹은 리소스에 대한 메타 데이터를 저장함. 
리소스 그룹의 위치를 지정하면 메타 데이터가 저장된 위치를 지정하는거임. 
규정 준수를 위해 데이터가 특정 영역에 저장되는지 확인하기 위함임. 

예를 들어, 미국에 데이터베이스 리소스를 만들었음. 
그리고 한국에 리소스 그룹을 만들었음. 
근데 이 미국의 데이터베이스는 한국에서 쓰면 안되는 리소스임. 
이 때, 한국의 리소스 그룹은 규정을 어긴 것이 됨. 
# Azure Resource Manager 잠금 만들기

구독 or 리소스 그룹 or 리소스 를 잠금하는 것. 

- **삭제 잠금**: 삭제 못하게
- **읽기 전용 잠금**: 읽기 전용으로 만듦. 수정불가
# Azure 리소스 다시 구성

리소스를 새 구독 or (구독 내부의) 새 리소스 그룹으로 이동해야 할 경우도 있겠지?

![[Screenshot 2024-12-27 at 09.49.33.png]]

리소스를 이동할 때는 원본 그룹, 대상 그룹 모두 잠금이 걸림(읽기 전용, 삭제 불가). 
하지만 여전히 해당 리소스는 사용 가능함. 
(가상 머신을 이동시키는 경우, 이동 중에도 가상머신 접근 가능)
가상 네트워크과 게이트웨이의 경우 처럼, 종속적인 리소스는 함께 이동해야 함.

그냥 포털에서 리소스 그룹 선택한 후 이동 버튼 누르면 됨..
이동할 리소스, 이동할 리소스 그룹 선택, 스크립트 업데이트 승인


리소스 이동 시 [여기](https://learn.microsoft.com/ko-kr/azure/azure-resource-manager/management/move-support-resources)를 참고할 것. 
각 리소스에 따른 제한사항이 자세히 서술되어 있음(자격증 준비에는 무시해도 될 듯 함). 

# 리소스 및 리소스 그룹 제거

포털 사용 시 그냥 리소스 그룹 삭제 버튼 딸깍으로 가능.
리소스만 삭제 할 때는 리소스 선택해서 삭제 버튼 딸깍..
이동도 여기서 함..
## PowerShell 사용 시

```PowerShell
Remove-AzResourceGroup -Name "YourResourceGroupName"
```

이름이 `YourResourceGroupName` 인 리소스 그룹을 제거하려면 위 처럼 입력하면 됨. 

# 리소스 제한 확인

나는 100만원만 쓸 수 있는데, 어쩌다보니 리소스 사용량이 100만원어치를 넘겨버리면 곤란하겠지?

![[Pasted image 20241227101601.png]]

Azure에서는 한도를 설정하고 위 사진 처럼 사용량 비율을 볼 수 있음. 
이 한도는 구독을 기준으로 한 한도임. 구독마다 한도가 다를 수 있다는 뜻. 
기본적으로 제공되는 한도를 늘려야 할 경우에는 링크가 따로 있음. 사진의 우상단 파란 버튼. 
모든 리소스에는 [Azure 제한](https://learn.microsoft.com/ko-kr/azure/azure-resource-manager/management/azure-subscription-service-limits?toc=%2Fazure%2Fnetworking%2Ftoc.json)에서 최대 한도가 있음. 
이 최대 한도를 넘어설 수는 없음.
