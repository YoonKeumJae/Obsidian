# Explanation

Docker 컨테이너가 시작할 때, 애플리케이션 또는 명령어를 실행합니다. 컨테이너는 실행 가능한 스크립트나 파일을 이미지 설정에서 가져옵니다. 컨테이너는 보통 잘 작동하는 기본 설정을 가져오지만, 필요하다면 바꿀 수 있습니다. 이 적용은 컨테이너의 프로그램이 정확히 당신이 원하는 대로 작동하도록 돕습니다. 

예를 들어, 기본 포트에서 리스닝하는 데이터베이스 컨테이너가 있고 같은 데이터베이스 인스턴스 컨테이너를 만들고 싶다면, 당신은 새로운 컨테이너와 이미 있는 컨테이너의 포트가 충돌하지 않도록 새로운 컨테이너의 포트 설정을 바꾸고 싶을 수 있습니다. 가끔 프로그램이 무거운 작업을 다루기 위해 더 많은 리소스를 필요로 하거나 프로그램이 적절히 작동하도록 특정한 설정을 주기 위해 환경 변수를 제공하고 싶다면, 당신은 컨테이너의 메모리를 늘리고 싶을 수 있습니다.

`docker run` 명령어는 기본 설정값을 오버라이딩 할 수 있는 강력한 명령어를 제공하여 원하는 대로 컨테이너가 동작할 수 있게 합니다. 그 명령어는 컨테인너의 행동을 커스텀 할 수 있는 몇 가지 플래그를 제공합니다. 

여기에 이것을 수행할 수 있는 몇 가지 방법이 있습니다. 

## Overriding the network ports

가끔 당신은 데이터베이스 인스턴스를 개발 목적과 테스팅 목적을 위해 분리하고 싶을 수 있습니다. 같은 포트에서 데이터베이스 인스턴스를 실행하는 것은 충돌을 발생할 수 있습니다. `docker run` 명령어에서 `-p` ㅇ옵션을 사용해 컨테이너 포트를 호스트 포트로 매핑할 수 있고, 이것은 어떠한 충돌 없이 여러 인스턴스를 실행할 수 있게 해줍니다. 

```
$ docker run -d -p HOST_PORT:CONTAINER_POER postgres
```

## Setting environment variabels

이 옵션은 환경변수 `foo`를 컨테이너 내부의 환경변수 `bar`의 값으로 세팅합니다. 

```
$ docker run -e foo=bar postgres env
```

다음과 같은 출력이 나옵니다: 

```
HOSTNAME=2042fe6ebe4
foo=bar
```

> [!Tip]
> `.env` 파일은 수많은 `-e` 플래그를 사용한 복잡한 명령어를 사용하는 일 없이 컨테이너의 환경변수를 설정하는 유용한 방법입니다. `.env` 파일을 사용하기 위해, `docker run` ㅁ명령어에 `--env-file` 명령어를 사용할 수 있습니다. 
> 
> ```
> $ docker run --env-file .env postgres env
> ```

## Restricting the container to consume the resources

`--memory` 플래그와  `--cpus` 플래그를  `docker run` 명령어에 사용해 컨테이너가 사용하는 CPU와 메모리의 양을 정의할 수 있습니다. 예를 들어, 호스트 머신에서 과도한 리소스를 소비하는 것을 막기 위해 Python API 컨테이너의 메모리 제한을 설정할 수 있습니다. 이것이 그 명령어입니다: 

```
$ docker run -e POSTGRES_PASSWORD=secret --memory="512m" --cpus="0.5" postgres
```

이 명령어는 컨테이너가 512MB의 메모리와 CPU의 절반의 코어를 사용하도록 제한합니다. 

>[!Monitor the real-time resource usage]
>`docker stats` 명령어로 컨테이너의 실시간 리소스 사용량을 모니터링 할 수 있습니다. 이것은 허용된 리소스가 적절한지 또는 수정이 필요한지 이해하는데 도움을 줍니다. 

`docker run` 명령어에 적절한 플래그를 사용함으로서, 당신은 컨테이너화 된 애플리케이션의 동작을 특정한 요구사항에 맞게 조정할 수 있습니다. 

# Try it out

이번 핸즈온 가이드에서, 컨테이너 기본값을 오버라이딩 하기 위해 `docker run` 명령어를 어떻게 사용하는지 알 수 있습니다. 

1. Docker Desktop을 [다운로드하고 설치합니다.](https://docs.docker.com/get-started/get-docker/)

### Run multiple instances of the Postgres database

1. 다음 명령어로 [Postgres 이미지](https://hub.docker.com/_/postgres?_gl=1*etqryd*_ga*MTM1OTg5MDQzNC4xNzQwNjI0NjU2*_ga_XJWPQMJYHQ*MTc0NDUyODg5Mi4xMy4xLjE3NDQ1MjkwMTYuNTMuMC4w)를 사용해 컨테이너를 시작하세요: 

```
$ docker run -d -e POSTGRES_PASSWORD=secret -p 5432:5432 postgres
```

이것은 백그라운드에서 Postgres 데이터베이스를 실행 할 것이고, 컨테이너 포트 `5432`와 호스트 머신의 포트 `5432`를 매핑합니다. 

2. 다른 포트로 매핑된 두 번째 Postgres 컨테이너를 시작합니다. 

```
$ docker run -d -e POSTGRES_PASSWORD=secret -p 5433:5432 postgres
```

이것은 백그라운드에서 다른 Postgres 컨테이너를 시작할 것이고, 컨테이너의 기본 postgres 포트인 `5432`번 포트에서 실행되지만, 호스트 머신의 `5433`번 포트와 매핑되어 있습니다. 당신은 새로운 컨테이너가 이미 실행중인 컨테이너와 충돌을 일으키지 않도록 호스트 포트를 오버라이딩 했습니다. 

3. Docker Desktop Dashboard의 Containers에서 두 컨테이너가 실행중인 것을 확인할 수 있습니다.
