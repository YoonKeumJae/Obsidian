# Explanation

이 가이드를 여기까지 따라왔으면, 컨테이너가 애플리케이션의 각 컴포넌트를 위한 고립된 프로세스를 제공한단는 것을 이해 할 것입니다. React 프론트엔드, Python API, Postgres 데이터베이스 등의 컴포넌트들은 각자의 샌드박스 환경에서 실행되고, 호스트 머신에서 완전히 고립됩니다. 이 고립은 보안과 의존성 관리에 뛰어나지만, 이것은 당신이 직접적으로 접근할 수 없음 또한 의미합니다. 예를 들어, 당신은 브라우저의 웹 앱에 접근할 수 없습니다. 

이것이 포트 개방이 존재하는 이유입니다. 

## Publishing ports

포트를 개방하는 규칙을 정의하는 것으로 네트워킹 고립을 뚫고 들어갈 수 있습니다. 예를 들어, 당신은 호스트의 `8080` 포트에서 요청이  컨테이너의 `80` 포트에 포워딩 되어야 한다는 것을 설정할 수 있습니다. `docker run` 명령어에 `-p` 또는 `--publish` 플래그를 추가함으로서 포트를 열 수 있습니다. 문법은 다음과 같습니다: 

```
$ docker run -d -p HOST_PORT:CONTAINER_PORT nginx
```

- `HOST_PORT`: 호스트 머신에서 트래픽을 받고 싶은 포트 넘버
- `CONTAINER_PORT`: 연결을 위해 리스닝 중인 컨테이너의 포트 번호

예를 들어, 컨테이너의 `80`번 포트를 호스트의 `8080`번 포트와 연결하고 싶다면: 

```
$ docker run -d -p 8080:80 nginx
```

이제, 호스트 머신의 `8080`번 포트로 들어오는 모든 트래픽은 컨테이너의 `80`번 포트로 포워딩 될 것입니다. 

>[!Important]
> 포트가 개방되었을 때, 기본적으로 모든 네트워크 인터페이스에게 개방됩니다. 이것은 기기에 접근하는 모든 트래픽이 배포된 애플리케이션에 접근할 수 있음을 의미합니다. 데이터베이스나 민감한 정보를 배포하는 것에 주의하세요. [배포된 포트에 대해 여기서 더 많은 정보를 얻으세요](https://docs.docker.com/engine/network/#published-ports)

## Publishing to ephemeral ports

때때로, 어떤 호스트 포트가 사용되는지 신경쓰지 않고 간단히 포트를 개방하고 싶을 수 있습니다. 이럴 경우, Docker가 포트를 결정하게 할 수 있습니다. 그러기 위해, 간단히 `HOST_PORT` 설정을 생략할 수 있습니다. 

예를 들어, 아래 명령어는 호스트의 일시적인 포트로 컨테이너의 `80`번 포트를 개방할 것입니다: 

```
$ docker run -p 80 nginx
```

일단 컨테이너가 실행되면, `docker ps` 명령어로 어떤 포트가 선택되었는지 볼 수 있습니다: 

```
docker ps
CONTAINER ID   IMAGE         COMMAND                  CREATED          STATUS          PORTS                    NAMES
a527355c9c53   nginx         "/docker-entrypoint.…"   4 seconds ago    Up 3 seconds    0.0.0.0:54772->80/tcp    romantic_williamson
```

이 예시에서, 앱은 호스트의 `54772`번 포트에 노출되었습니다. 

## Publishing all ports

컨테이너 이미지를 생성할 때, `EXPOSE` 명령어는 패키지 된 애플리케이션이 특정한 포트에서 사용될 것을 나타냅니다. 이 포트들은 기본적으로 배포되지 않습니다. 

`-P` 또는 `--publissh-all` 플래그와 함께, 노출된 모든 포트를 일시적인 포트로 자동으로 배포할 수 있습니다. 이것은 개발 또는 테스팅 환경에서 포트 충돌을 예방하기에 꽤 유용합니다. 

예를 들어, 아래 명령어는 이미지에 의해 설정된 모든 노출된 포트를 배포할 것입니다: 

```
$ docker run -P nginx
```

# Try it out

이번 핸즈온 가이드에서, 당신은 웹 애플리케이션을 배포하기 위해 CLI와 Docker Compose를 사용해 컨테이너 포트를 배포하는 법을 배울 것입니다. 

## Use the Docker CLI

이번 단계에서, 당신은 컨테이너를 실행하고 Docker CLI를 사용해 컨테이너의 포트를 배포할 것입니다. 

1. Docker Desktop을 [다운로드하고 설치하세요](https://docs.docker.com/get-started/get-docker/). 
2. 터미널에서, 새로운 컨테이너를 실행하기 위해 다음의 명령어를 실행하세요: 

```
$ docker run -d -p 8080:80 docker/welcome-to-docker
```

처음 나오는 `8080`은 호스트의 포트입니다. 이것은 컨테이너 내부에서 실행되는 애플리케이션으로의 접근에 사용될 당신의 로컬 머신의 포트입니다. 두번째 `80`은 컨테이너의 포트입니다. 이것은 컨테이너 내부의 애플리케이션이 외부에서 들어오는 연결을 듣는 포트입니다. 따라서, 이 명령어는 호스트의 `8080` 포트와 컨테이너의 `80`번 포트를 연결합니다. 

3. Docker Desktop DashboardDML Containers 탭으로 들어가 배포된 포트를 확인합니다. 

![A screenshot of Docker Desktop Dashboard showing the published port](https://docs.docker.com/get-started/docker-concepts/running-containers/images/published-ports.webp)

4. 컨테이너의 **Port(s)** 컬럼의 링크를 클릭하거나 브라우저의 http://localhost:8080 으로 접속해서 웹 사이트를 열어봅니다. 

![A screenshot of the landing page of the Nginx web server running in a container](https://docs.docker.com/get-started/docker-concepts/the-basics/images/access-the-frontend.webp?border=true)

## Use Docker Compose

이 예시는 Docker Compose로 같은 애플리케이션을 실행 할 것입니다: 

1. 새로운 디렉토리를 생성하고, 그 디렉토리에서 `compose.yaml` 파일을 생성해 다음 내용을 작성합니다: 

```
services:
  app:
	image: docker/welcome-to-docker
	ports: 
	  - 8080:80
```

`ports` 설정은 포트 정의를 위해 조금 다른 형태의 문법을 가집니다. 이 경우, `docker run` 명령어에서 사용한 `HOST_PORT:CONTAINER_PORT`와 같습니다. 

2. 터미널을 열고 전 단계에서 생성한 디렉토리로 이동합니다. 
3. `docker compose up` 명령어로 애플리케이션을 실행합니다. 
4. 브라우저를 열고 http://localhost:8080 에 방문합니다.
